# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

This is the **source repository for SDLE (Spec Driven Lifecycle Engine)** — a Claude Code skill that orchestrates a gated 18-phase SDLC workflow wrapping GitHub SpecKit. The "code" here is markdown prompt files, not compiled software. There is no build, lint, or automated test step.

**Validation** is done by running the skill: this repo carries a test fixture (`requirements/todo-api.md`) so the workflow can be exercised in place by saying `start workflow`. Runtime artifacts generated by such runs (`.workflow/`, `.specify/`, `design/`, `reviews/`, `clarifications/`) are gitignored — never commit them.

## Architecture

The skill lives at `.claude/skills/sdle/` and is deliberately split for lazy loading:

- **`SKILL.md`** — orchestrator entry point, always loaded. Contains the command dispatcher, state management (Step 9), error handling, and the **Internal Constants** (PHASE_SEQUENCE, NEXT_PHASE, PHASE_TO_GATE_KEY, GATE_PHASES, ARTIFACT_OWNERSHIP, PHASE_LABEL_MAP, PROGRESS_MAP). These constants are the **single source of truth** — the modules explicitly assume them from context and must never duplicate them.
- **`modules/phase-execution.md`** — per-phase execution logic, drift check (Step 0), idempotency check (Step 0b), guidance-file injection. Loaded only when executing a phase.
- **`modules/gate-protocol.md`** — approval gate display, rejection/remediation flow, GATE_TO_EXECUTION_PHASE table. Loaded only at gate phases.
- **`modules/security-review.md`** — evidence-based security review template. Loaded only at Phase 17.
- **`templates/state.json`** — initial state template. Must stay byte-for-byte consistent with the JSON template embedded in SKILL.md Step 9.

Runtime state lives in the *target project's* `.workflow/state.json` (canonical source of truth) plus an append-only `audit.md`. The skill is a finite state machine driven by that file — every turn reads state first, and gates can only be passed by explicit user `approve`.

Documentation, layered:
- `README.md` — quick-start and lookup reference (phase table, commands, state schema).
- `docs/SDLE-Reference-Guide.md` — the canonical enterprise reference (design rationale, per-phase detail, glossary, appendices).

Historical context (do not treat as current spec): `Base-Prompt.md`, `MVP-Prompt.md`, and root `requirements.md` are the original prompts that produced SDLE.

## Non-Negotiable Design Invariants

Any edit to the skill files must preserve these (they are the product):

1. **State first** — read `.workflow/state.json` before any action; emit the state assertion header first.
2. **Gate discipline** — never advance past a gate without explicit `approve`; no forward jumps.
3. **SpecKit opacity** — `speckit-*` skill names and internals are never shown to the user (verbose mode excepted).
4. **Gate content in conversation** — artifact content is displayed at every gate; the user never opens a file to approve.
5. **Fail safe** — on any failure, freeze status; never advance the phase.

## Cross-File Sync Rules (the main way changes go wrong)

When changing skill behavior, these files reference each other and must be updated together:

- **Version bump**: the version string appears in `SKILL.md` (frontmatter description + heading), `README.md` (title + version-history table), `templates/state.json` (`workflow_version`), and the Reference Guide header. Every state-schema change also requires a new row in the **version migration table** (SKILL.md Step 9) so older `state.json` files upgrade in place.
- **Adding a phase**: update PHASE_SEQUENCE, NEXT_PHASE, PHASE_LABEL_MAP, PROGRESS_MAP in SKILL.md, add a block to `modules/phase-execution.md`, and update the phase tables in README.md and the Reference Guide. All `N/18` progress strings derive from PROGRESS_MAP only.
- **Adding a gate**: additionally register it in GATE_PHASES, PHASE_TO_GATE_KEY, ARTIFACT_OWNERSHIP, the `approvals` object in both state templates, and GATE_TO_EXECUTION_PHASE in `modules/gate-protocol.md`.
- README.md's command table, file layout, and state-schema section mirror SKILL.md — keep them consistent.

## Platform Note

The skill's embedded shell commands are **PowerShell/Windows** (e.g. `Get-FileHash -Algorithm SHA256`, `New-Item -ItemType Directory -Force`). Keep new embedded commands PowerShell-compatible.
